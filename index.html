The frontend model

              
UI = F(state)

              

                A component declares the data it needs as a query. That query stays up to date, frame by frame. 
                No cache invalidation, refetch
                choreography, or hand-written synchronization.
              

              

                01 query once→
                02 write state→
                03 every view is current

01 / Declare the view

                
The query is the contract.

                

                  The query on the left doesn't fetch eight rows and leave you hanging. It
                  creates a maintained view: the newest eight visible shapes, in order, for as
                  long as the component needs it.

02 / Render current state

                
The UI is a function of the query.

                

                  The component reads the query’s current rows. The binding schedules a render
                  when that query receives an update. Application code does not work out what changed
                  or patch the collection by hand.
                

                

                  Loading the initial result and maintaining it are the same abstraction. Once
                  materialized, recent.data is the current answer now and forever.

03 / Change state once

                
Transactions are the only update path.

                

                  Dragging a shape writes a row. Inside that same call, the engine derives the
                  consequences and updates every affected query. When the promise resolves,
                  the next paint already has the right data.
                

                
Try it. Drag a shape and watch the query panels pulse together.

04 / Let queries do the bookkeeping

                
One row can have many derivations.

                

                  Recoloring moves a count between palette groups. Resizing can reseat the
                  leaderboard. Any edit moves the shape to the top of the feed. Dragging across a
                  cell boundary removes it from one canvas query and inserts it into its neighbor.
                

                

                  These are not four update handlers. They are four declarations.

05 / Model relationships, not effects

                
A tiny write can have a large, exact fan-out.

                

                  Whether a shape is visible is a function of whether its layer is on. Hide the
                  layer: one row changes and every dependent query hides the correct shapes.
                

                

                  You do not walk the shapes, clear caches, or notify panels. The join already
                  describes the consequence.
                

                
On the canvas Click an eye in “layers” to make one write fan out across thousands of rows.

06 / Change data, not query identity

                
Even ephemeral UI state can be declarative.

                

                  The selected ids live in a table. Dragging a selection box writes only the rows crossing its edge. Impacted queries are updated atomically.
